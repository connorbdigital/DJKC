# Anything.com, read from the Studio

The Studio can now list the projects on [anything.com](https://www.anything.com) — the
account that holds **sitebuildup** — without the key ever reaching a browser.

## What the API actually is

- Base `https://api.anything.com`.
- `GET /v0/api/me` → `{id, email, name, organizations[]}`, and each organisation carries
  `plan`, `planDisplayName`, `isPaid` and `creditsBalance`.
- `GET /v0/api/projects?organizationId=&query=&limit=` → `{projects[]}` with `id`, `name`,
  `slug`, `organizationId`, `organizationName`, `createdAt`, `updatedAt`. The limit is 100.
- **Auth is HTTP Basic with the key as the username and an empty password** — literally
  `Authorization: Basic base64("anything_xxx" + ":")`. That detail is the one thing that
  cannot be guessed, which is why it came from the docs
  (`https://www.anything.com/docs/llms.txt`) rather than from memory.
- Errors come back as `{error, details, message}` with 400/401/403/404.

The API can also create, duplicate, rename and delete projects. The Studio proxies **none
of those**.

## What was built

| Piece | What it does |
| --- | --- |
| `studio/src/anything.ts` | The base URL, the two paths, the key names, the response types, `basicAuth()`, and `anythingTarget()` — the allowlist |
| `studio/api/anything.ts` | The server route: `POST` in, `GET` out, 12-second timeout, JSON passed through, the key added here and never echoed |
| `studio/src/components/Anything.tsx` | The tab: project list, organisation, slug, last-updated, credits, a filter |
| `studio/src/anything.test.ts` | Six tests over the rules and the handler |

The allowlist is exact-path, not a prefix: `/v0/api/projects/123/delete` is refused, and so
are absolute URLs, `..`, `\`, `@`, `//`, a missing leading slash and anything over 300
characters. A test drives each of those.

## Two key names, on purpose

The docs call it `ANYTHING_API_KEY`. The key on the Vercel project currently lives under
`Anything_Key`. The route reads `ANYTHING_API_KEY` first and falls back to `Anything_Key`,
so either name works and nothing breaks while it is tidied up. Renaming it in Vercel keeps
the value.

## What a visitor is told

A **missing** key and a **rejected** key read differently, because the fix is different:

- missing → "Set `ANYTHING_API_KEY` on this project…", and the shelf table already lists the
  key with what breaks without it;
- `401` → "Anything rejected that key. Check it is an API key, not a session token."

Neither message can contain the key: the handler returns upstream bodies, and the browser
never sends one.
