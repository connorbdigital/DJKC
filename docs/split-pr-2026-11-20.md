# Splitting PR #18 into two PRs — the tested recipe

*Process note, 20 Nov 2026. Not part of the product: delete it once the decision
is made either way.*

PR [#18](https://github.com/connorbdigital/DJKC/pull/18) carries three commits on
one branch:

| Commit | Contents | Tree it touches |
| --- | --- | --- |
| `52f697c` | The shop: Exommeece, twelve departments, the four commission routes | `commerce/`, `docs/`, 2 studio files |
| `dff13a2` | Shop screenshots and the deliverables index | `docs/` |
| `446754f` | The Atlas and the blog plan | `studio/`, `docs/` |

## Recommendation: leave it as one PR

The commits are already the split. A reviewer reads commit 1 as the shop and
commit 3 as the Atlas, and the diff of each is coherent on its own. Splitting
costs a re-run of CI, a second set of screenshots to keep in step, and — as the
measurements below show — the two halves are coupled through the evidence the
blog posts cite. There is no technical reason the split is *needed*.

Split only if the review is being done by two different people, or if you want
to ship the shop this week and the Atlas next.

## If you do split: shop first, Atlas second

This is the only order where both PRs are green on their own. The commands below
were run against a throwaway clone of `main` (`6c881b0`), not inferred.

### PR A — the shop

```bash
git fetch origin
git checkout -b shop-exommeece origin/main
git cherry-pick 52f697c dff13a2
git push -u origin shop-exommeece
```

**Result: no conflicts.** The resulting tree is identical to `dff13a2`'s
(`0b72d83…`), so PR A is exactly the shop work and nothing else.

### PR B — the Atlas, after A merges

```bash
git checkout -b atlas origin/main        # now includes the merged shop
git cherry-pick 446754f
git push -u origin atlas
```

**Result: no conflicts.** The resulting tree is identical to this branch's head
(`4b46a09…`), so A + B together are byte-for-byte what #18 contains today.

Then close #18 without merging: it is superseded by two PRs whose content is the
same.

## Why the other order does not work

Cherry-picking the Atlas onto today's `main` first:

- **One conflict:** `docs/README.md`. `main` has no `docs/` directory at all —
  the shop commit creates it — so the Atlas commit modifies a file that does not
  exist yet.
- **One failing test:** `atlas.test.ts` → *"points at files that exist, so the
  proof is real"*. Six of the 21 proof paths in `studio/src/atlasBriefs.ts` are
  files the shop commit adds:

  ```
  commerce/src/siteModel.ts
  commerce/catalogue/render.ts
  commerce/catalogue/site.ts
  commerce/catalogue/scripts/build-site.mts
  commerce/src/affiliate.ts
  commerce/src/affiliate.test.ts
  ```

That failure is the point of the briefs rather than a bug: every post argues
from a number, and the number has to point at code that exists. On an
Atlas-first branch the honest fix is to weaken those citations — which is a
worse PR than the coupling it avoids.

## What was not changed

Nothing in this repository was touched to produce this note: the probes ran in
`/tmp`, on a clone. PR #18 is still open, unmerged, with all checks passing.
